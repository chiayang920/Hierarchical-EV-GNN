## Confirmed root cause

The original `write_log_row()` constructed a new `csv.DictWriter` from each row's keys but wrote the header only for the first row. Because a `train_episode` row was written first, the persistent header contained only eight base fields. Later evaluation rows wrote 43 values without matching header names.

This was an artefact-serialisation defect. There is no evidence of a reward-computation, policy, checkpoint, evaluator, or training-execution failure.

## v2 producer-side repair

The strict package validator remains unchanged. `train_td3_gnn.py` now:

1. reads the established header before appending;
2. preserves existing field order;
3. appends newly observed metric names to the schema;
4. atomically rewrites prior valid rows with blank values for newly introduced fields;
5. appends subsequent rows using the established header;
6. uses `extrasaction="raise"` to prevent silent data loss;
7. rejects pre-existing rows containing unnamed extra columns.

This ensures:

```text
ALL_ROWS_HAVE_EQUAL_COLUMN_COUNT=YES
EVAL_MEAN_REWARD_NAMED_COLUMN=YES
DICTREADER_NONE_KEY=ABSENT
```
